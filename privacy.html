개인정보처리방침 (mail-relay)

시행일: 2026년 10월 22일

1. 목적

mail-relay는 운영자 본인이 소유한 POP3 메일함의 새 메일을 운영자 본인의 Gmail 계정으로 옮기기 위한 개인용 도구입니다.

2. 사용하는 Google 권한

  • gmail.insert: 가져온 메일을 사용자의 Gmail 메일함에 넣기 위해 사용합니다.
  • gmail.labels: 메일함 주소별 라벨을 확인하거나 만들기 위해 사용합니다.

mail-relay는 Gmail의 기존 메일을 읽거나, 메일을 발송하거나, 삭제하지 않습니다.

3. 데이터 처리

  • 메일은 원래 메일 서버에서 받아 사용자의 Gmail로 바로 전달하며, 중계 서버에 메일 내용을 보관하지 않습니다.
  • 중복 전달을 막기 위해 메일의 고유 번호(UIDL)만 중계 서버에 기록합니다.
  • Google 인증 정보와 메일 계정 접속 정보는 중계 서버에 접근 권한을 제한해 저장합니다.
  • 어떠한 데이터도 제3자에게 제공하거나 판매하지 않으며, 광고나 분석에 사용하지 않습니다.

4. Google API 서비스 사용자 데이터 정책 준수

mail-relay가 Google API로부터 받은 정보의 사용 및 다른 앱으로의 전송은 제한적 사용 요구사항을 포함한 Google API 서비스 사용자 데이터 정책을 따릅니다.

5. 권한 철회

사용자는 언제든지 Google 계정 권한 설정에서 mail-relay의 접근 권한을 해제할 수 있습니다.

Privacy Policy (mail-relay)

Effective date: October 22, 2026

1. Purpose

mail-relay is a personal tool that copies new messages from the operator's own POP3 mailboxes into the operator's own Gmail account.

2. Google permissions used

  • gmail.insert: to insert fetched messages into the user's Gmail mailbox.
  • gmail.labels: to look up or create a label for each source mailbox.

mail-relay does not read existing Gmail messages, send email, or delete email.

3. Data handling

  • Messages are passed directly from the source mail server to the user's Gmail; message content is not stored on the relay server.
  • Only message identifiers (UIDL) are stored to prevent duplicate delivery.
  • Google credentials and mailbox login details are stored on the relay server with restricted access.
  • No data is shared with or sold to third parties, or used for advertising or analytics.

4. Google API Services User Data Policy

mail-relay's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

5. Revoking access

You can revoke mail-relay's access at any time in your Google Account permissions.
